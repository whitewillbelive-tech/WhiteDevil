# 데이터 설계와 복구

## 단일 원본과 연결

`schemaVersion: 2`의 JSON에 `project`, 7개의 `seasons`, `characters`, `events`, `locations`, `groups`를 보관합니다. 주요 레코드는 이름과 독립된 고유 `id`를 사용합니다. 이름 수정으로 연결이 깨지지 않습니다. 데이터는 빈 상태에서 시작하며 사용자가 입력하지 않은 작품 설정을 생성하지 않습니다.

공통 인물·장소·집단은 전역 레코드 하나와 `seasonStates[1..7]`을 가집니다. 시즌 전용 인물은 `type: guest`, `homeSeason`으로 표시 범위를 제한하며, 분류를 전환해도 기존 시즌 자료를 유지합니다. 인물 소속은 인물의 `seasonStates[s].groupIds`가 원본입니다. 집단 화면의 구성원 목록은 이를 조회하고 수정합니다.

사건은 `season`, `order`, 자유로운 시간 표기 `timeLabel`을 가집니다. 빈 시간은 미정입니다. `locationId`, 해당 장소·시즌의 `zoneId`, `personIds`, `participantRoles`, `groupIds`, `followingEventIds`로 관련 자료를 참조합니다. 인물의 관계와 시즌 변화 원인도 ID로 연결합니다.

장소 전개도는 `seasonStates[s].plan`의 편집 가능한 도형 목록입니다. 각 도형은 ID·유형·이름·메모·좌표·크기·색상·표시 방식을 가집니다. 시즌 복사는 깊은 복사로 수행하여 원본과 복사본을 독립 편집합니다. 구역 ID는 장소와 시즌 안에서 유일합니다. 사건의 구역은 장소와 시즌을 함께 사용해 해석합니다.

`status`는 사용자가 선택하는 `draft`(검토 중), `confirmed`(확정), `held`(폐기·보류)입니다. 앱이 미확정 내용을 보완하거나 확정 상태를 자동으로 부여하지 않습니다.

## 검증과 이관

`ArchiveData.normalize()`는 v1 또는 v2를 복제해 필요한 기본 필드를 채우고 v2로 검증합니다. 기존 값과 안전한 추가 메타데이터를 보존합니다. 지원하지 않는 버전, 중복 ID, 잘못된 시즌·도형 수치, 존재하지 않는 연결, 잘못된 참여 역할, 장소 계층 순환 등을 거부합니다. 명시적으로 입력하지 않은 서사 내용은 채우지 않습니다.

삭제 전에 참조를 검사하며, 삭제 후 사건·관계·소속·구역 등의 끊어진 연결을 정리합니다. 편집 취소를 통해 삭제와 연결을 함께 복원할 수 있습니다.

## 저장 키

`ArchiveData.KEYS`가 다음 이름을 제공합니다.

| 키 | 용도 |
| --- | --- |
| `white-devil-story-archive-v2` | 현재 데이터 |
| `white-devil-story-archive-v1` | 초기 버전 원본, 이관 시 유지 |
| `white-devil-story-archive-recovery` | 가져오기 전 또는 복구 전 상태 |
| `white-devil-story-archive-damaged` | 명시적 복구 과정에서 보존한 원본 |

이 키들은 앱 코드에 포함된 자격 증명이 아니라 브라우저 저장 항목의 이름입니다. 앱에는 서버 계정이나 원격 데이터 저장소가 없습니다.

일반 저장은 현재 저장 내용을 읽었던 시점과 비교해 다른 창에서 생긴 변경을 덮어쓰지 않도록 합니다. 가져오기는 전체 JSON을 검증한 뒤 복구 슬롯을 확보하고 현재 데이터에 씁니다. 쓰기 실패나 손상 데이터를 정상 저장으로 표시하지 않습니다. 복구 시 현재 데이터 기록에 실패하면 기존 복구 자료를 유지합니다.

원격 동기화·다중 사용자 편집·서버 백업·암호화 저장은 현재 범위에 포함하지 않았습니다. 이후 사용자 관리 저장소를 도입할 때는 출처와 권한, 충돌 처리, 백업 정책을 별도로 설계해야 합니다. 현재의 안정적인 ID와 스키마 버전은 기존 자료의 명시적인 이관에 사용할 수 있습니다.
