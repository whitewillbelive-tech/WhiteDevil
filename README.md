# 《하얀 악마》 설정 아카이브

일곱 시즌의 인물·사건·장소·집단을 연결하는 독립 웹앱입니다. 첨부된 초기 버전의 기능을 바탕으로 개발했으며, 실제 작품의 설정은 임의로 입력하지 않았습니다.

## 실행

설치나 빌드 없이 `index.html`을 Chrome 또는 Edge로 열 수 있습니다. 브라우저마다 `file://` 저장 정책이 다르므로, 장기간 집필에는 같은 주소의 로컬 서버를 사용하세요.

```bash
cd WhiteDevil
python3 -m http.server 8000 --bind 0.0.0.0
```

Windows에서는 `python3` 대신 `py`를 사용할 수 있습니다. 브라우저에서 `http://127.0.0.1:8000`을 엽니다. 서버를 종료하려면 `Ctrl+C`를 누릅니다. 개인 PC에서 외부 접속이 필요 없으면 `--bind 127.0.0.1`을 사용하세요.

## 사용

- 최상단의 전체 / 시즌 1~7 선택은 모든 탭에 적용됩니다. 전체 개요에서 시즌 제목과 핵심 줄거리를 기록합니다.
- **인물**: 공통·시즌 전용 인물을 나누고, 공통 인물의 7개 시즌 상태를 한 레코드에 보관합니다. 인물 × 시즌 비교표로 변화와 소속을 비교합니다. 분류를 전환해도 기존 시즌 기록을 보관합니다.
- **사건**: 시간별·공간별·인물별로 동일한 사건을 탐색합니다. 장소의 해당 시즌 구역, 참여 인물의 역할, 집단, 후속 사건을 연결합니다.
- **배경**: 장소와 집단을 관리합니다. 장소 전개도에서 도형 생성·이동·크기 변경·색상·표시 방식·실행 취소·확대·화면 이동과 시즌 간 복사를 지원합니다. 인물 소속과 집단 구성원은 같은 데이터를 사용합니다.
- 각 기록의 **검토 중 / 확정 설정 / 폐기·보류** 상태는 사용자가 직접 지정합니다. 이름을 바꿔도 ID와 연결은 유지됩니다. 삭제 시 관련 참조를 알리고 해제합니다.
- 입력은 즉시 자동 저장됩니다. 상단의 편집 취소·다시 실행으로 변경을 복구할 수 있습니다. 전개도에는 별도 실행 취소가 있습니다.

## 데이터 보관과 백업

저장소는 **현재 브라우저 프로필과 사이트 출처에 속한 `localStorage`**입니다. 서버·GitHub·다른 프로젝트로 설정 데이터가 전송되거나 동기화되지 않습니다. 서버를 실행해도 데이터가 서버 디스크에 저장되는 것은 아닙니다.

1. 중요한 편집 후 **JSON 백업**으로 전체 데이터를 내려받아 별도 폴더나 개인 백업 저장소에 보관합니다.
2. 다른 브라우저·PC·배포 주소로 옮길 때 **가져오기**로 JSON을 선택합니다. 구조와 연결을 검증한 다음 전체 교체 여부를 확인합니다.
3. 가져오기 직전 데이터는 복구 슬롯에 보관됩니다. **이전 상태 복구**로 전환할 수 있습니다. 복구 슬롯은 영구 백업을 대신하지 않습니다.

초기 버전의 v1 JSON을 가져올 수 있으며, 같은 출처에 남은 v1 저장 데이터도 v2로 읽습니다. 원본 v1 키를 덮어쓰지 않습니다. 손상 데이터가 발견되면 자동으로 빈 데이터로 바꾸지 않고 원본 다운로드와 명시적 복구를 안내합니다. 저장 실패 시 경고가 표시되므로 창을 닫기 전에 JSON을 내려받으세요. 다른 창의 저장 변경을 감지하면 덮어쓰기를 막습니다.

`http://localhost:8000`, `http://127.0.0.1:8000`, 다른 포트, `file://`, 새 배포 도메인은 서로 저장 위치가 다를 수 있습니다. 주소를 바꾸기 전에 JSON을 내보내세요. 브라우저 데이터 삭제·시크릿 모드 종료·브라우저 프로필 분실은 로컬 데이터 손실로 이어질 수 있습니다.

## 개발과 검증

앱에는 외부 라이브러리나 빌드 도구가 필요하지 않습니다. 자동 검증에는 Node.js 24, Python 3.12, Playwright와 Chromium을 사용합니다.

```bash
node --test --test-isolation=none tests/data.test.js
python3 -m pip install -r requirements-dev.txt
python3 -m playwright install chromium
```

시스템 Chromium이 `/usr/bin/chromium`에 있으면 다음 명령으로 브라우저 검증을 실행합니다.

```bash
python3 tests/browser_test.py
```

다른 위치의 Chromium을 사용할 때는 `CHROMIUM_PATH` 환경 변수를 지정하세요. Playwright가 설치한 브라우저의 경로는 아래 명령으로 확인할 수 있습니다.

```bash
python3 -c "from playwright.sync_api import sync_playwright; p=sync_playwright().start(); print(p.chromium.executable_path); p.stop()"
```

브라우저 검증은 임시 HTTP 서버와 격리된 브라우저 컨텍스트에서 수행하며, 검증 자료를 정식 설정에 섞지 않습니다. 스크린샷은 `tests/artifacts/`에 생성됩니다. GitHub Actions의 [CI 설정](.github/workflows/ci.yml)은 데이터 검증과 Chromium 자동 검증을 실행합니다. 로컬 통과와 GitHub에서의 CI 실행은 별개의 결과입니다.

실제 검사 결과와 필수 검수 조건별 증거는 [검증 결과](docs/verification.md)에 기록했습니다.

## 소스와 운영 범위

| 파일 | 역할 |
| --- | --- |
| `index.html`, `favicon.svg` | 앱 진입점과 아이콘 |
| `app.js`, `styles.css` | 화면·편집·탐색·저장 상태 |
| `data.js` | 스키마·v1 이관·참조 검증·로컬 저장·복구 |
| `plan.js`, `plan.css` | 시즌별 구조화된 전개도 편집 |
| `tests/` | 별도 검증 자료와 자동 테스트 |

자세한 데이터 구조는 [데이터 설계](docs/data-model.md), 초기 버전 확인 결과와 배포 범위는 [기준본 및 운영 확인](docs/starter-review.md), Windows에서의 최종 사용 확인 항목은 [수동 검수](docs/manual-checks.md)를 참고하세요.

GitHub Pages 배포는 같은 [CI 워크플로](.github/workflows/ci.yml)에 포함되어 있습니다. 모든 브랜치와 PR에서 테스트하며, `main`의 push·수동 실행에서는 테스트를 통과한 정적 파일만 Pages로 배포합니다. 브라우저 검증도 실제 배포할 `_site` 폴더를 대상으로 실행합니다. 다른 프로젝트 소스·데이터와 자동 연동하지 않습니다.

현재 클라우드 프록시가 GitHub API와 Pages 주소를 차단하여 실행 `42200562155`의 원본 로그, 새 원격 CI 결과, PR·병합·공개 배포를 확인하지 못했습니다. 배포 완료 상태가 아닙니다. 수정 내용과 적용 경로는 [Pages 배포 안내](docs/deployment.md)를 참고하세요.
