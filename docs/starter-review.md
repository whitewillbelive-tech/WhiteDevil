# 초기 기준본과 운영 확인

제공된 `white_devil_site_starter.zip`의 `white-devil-archive`를 별도 디렉터리에 해제했습니다. `CODEX_SITE_HANDOFF.md`, `README.md`, `TEST_CASES.md`와 실제 HTML·CSS·JS를 검토하고 초기 버전을 로컬 HTTP 서버에서 실행했습니다. ZIP의 문서는 기준 자료로 읽었으며, 작업 범위는 사용자의 정식 개발 요청에 맞췄습니다.

## 초기 버전에서 실제 확인한 내용

격리된 Chromium 브라우저에서 아래 동작을 확인했습니다.

- 전체 및 시즌 1~7의 8개 필터, 전체 개요와 인물·사건·배경 화면 전환
- 인물 입력 후 새로고침 보존
- 사건 생성과 장소 전개도의 도형 생성
- 해당 검증에서 처리되지 않은 브라우저 오류 없음

공통 인물을 시즌 전용으로 바꾼 뒤 다시 공통으로 바꾸면 다른 시즌의 기록이 사라지는 문제를 재현했습니다. 새 구현은 분류 전환 시 기존 시즌 상태를 보관합니다.

초기 UI에는 설정 상태, 공간·인물별 사건 보기, 사건의 구역 연결, 전개도 실행 취소·확대·화면 이동·색상, 전체 편집 취소와 깊은 JSON 검증이 없었습니다. 새 구현의 검증은 초기 기준본 확인과 별도로 수행합니다.

## 저장소와 배포

선택된 독립 저장소는 `whitewillbelive-tech/WhiteDevil`입니다. 작업 시작 시 체크아웃에는 초기 `README.md`만 있었고, 기존 배포 워크플로는 없었습니다. 개발은 별도 `feat/white-devil-archive` 브랜치에서 진행합니다. 이 저장소 밖의 다른 창작 프로젝트를 조사하거나 수정할 필요가 없는 구성입니다.

기존 플랫폼 인증을 사용한 Git 원격 읽기 접근은 확인되었습니다. GitHub Pages 설정의 읽기 전용 API 조회는 `Forbidden`으로 거부되어, 기존 배포 설정·주소·상태를 확인하지 못했습니다. 이 결과만으로 Pages가 없거나 비활성이라고 단정하지 않습니다. 접근이 확인되지 않은 서비스로 소스나 사용자 설정을 전송하지 않았습니다.

이 앱은 빌드 없는 정적 파일로 배포할 수 있습니다. 실제 호스팅 대상으로 파일을 게시하고 브라우저에서 확인하기 전까지는 배포 완료가 아닙니다. 새 주소는 기존 로컬 출처와 다른 저장소를 가지므로 JSON 내보내기·가져오기로 자료를 옮겨야 합니다.
